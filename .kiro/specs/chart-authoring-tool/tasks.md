# Implementation Plan

- [x] 1. 基盤: 共有型・内部型・ツールルートの土台

- [x] 1.1 譜面フォーマットの共有型と検証を定義する
  - 譜面をバージョン付きの構造として定義し、出典（ファイル / YouTube・動画 ID・ファイル名・時刻補正）とステップ列（時刻・入力種別・信頼度・由来）を表現できるようにする
  - 入力種別の値域を既存のアーケードコントローラの入力種別に完全に一致させ、独自の種別を新設しない
  - 未知のバージョン、型の不一致、不正な入力種別、範囲外の数値を、それぞれ区別できる形の検証結果として返す。検証は最初の 1 件で打ち切らず、不正箇所を場所付きですべて列挙する
  - 後続の練習モードスペックから利用できるよう、共有型モジュールから再エクスポートする
  - 完了状態: 妥当な譜面が検証を通過し、バージョン不正・入力種別不正・信頼度の範囲外がそれぞれ固有の理由とともに拒否されることが単体テストで確認できる
  - _Requirements: 8.1, 8.2, 8.7_

- [x] 1.2 ツール内部で使う型と解析パラメータの既定値を定義する
  - 動画フレーム上の矩形を解像度非依存の正規化座標で表す型、動画の同一性を照合するためのキー（ファイル名・尺・解像度）、スロット校正、走査の中間表現、編集用ステップを定義する
  - 解析パラメータ（ブースト急減の閾値と時間窓、CHARGE 点灯の輝度閾値と確定に要する連続フレーム数、連射を畳む間隔、グリフ照合の許容距離）を型と既定値の両方で定義する
  - コマ送りの単位時間、Undo の上限件数、走査可能な最大尺、永続化キーを定数として一箇所にまとめる
  - 完了状態: 解析・編集・入出力の各層が参照する型と定数が揃い、型チェックが通る
  - _Requirements: 3.1, 4.5, 7.7, 8.8_

- [x] 1.3 ツール専用ルートの骨組みを用意する
  - 主導線のメニューから辿れない専用ルートを新設し、プレースホルダ画面を表示する
  - 練習画面が使う横画面ガードでは包まず、縦横どちらの向きでも操作できるようにする
  - ページ全体を高さいっぱいのレイアウトとし、縦に長くなる領域だけが内部でスクロールする構造にする（アプリ全体が本文スクロールを禁じているため）
  - 完了状態: 専用ルートに直接アクセスすると画面が表示され、メニューにはリンクが追加されておらず、縦向きでも警告が出ないことを確認できる
  - _Requirements: 9.1, 9.2_

- [x] 1.4 (P) ツール配下のアナリティクス計測を除外する
  - 計測を行わないパスの定義を単一の設定点として新設し、ページビュー送信と Google Analytics スクリプトの両方がそれを参照するようにする
  - ページビュー送信は除外パスで呼ばれないようにする
  - Google Analytics のスクリプトを、現在のパスを判定できる薄いクライアント要素として切り出し、除外パスでは描画しないようにする。除外パス以外での出力内容は現状から変更しない
  - 完了状態: ツールのパスでページビュー送信と計測スクリプトのいずれも発生せず、既存ページでは従来どおり計測スクリプトが出力されることをテストで確認できる
  - _Requirements: 9.3_
  - _Boundary: excludedPaths, AnalyticsPageViewTracker, GoogleAnalyticsScripts_

- [x] 2. 解析ロジック: 画面非依存の純関数層

- [x] 2.1 画素領域から記述子を導く処理を作る
  - 弾数の桁セルから、大きさと明るさの違いに影響されにくい正規化済みの特徴ベクトルと、描画インクの割合を求める
  - CHARGE 表示領域から正規化輝度を求める
  - ブーストゲージ領域から充填率を求める
  - 特徴ベクトル同士の距離を求める関数を用意し、以降のクラスタリングと照合が同じ尺度を使うようにする
  - 画面描画の仕組みに一切依存させず、画素の配列だけを入力として受け取る
  - 完了状態: 手で組んだ画素配列に対して期待どおりの特徴量が返り、空セルがインク割合から判別できることが単体テストで確認できる
  - _Requirements: 3.1_

- [x] 2.2 (P) 桁グリフのクラスタリングと数字解決を作る
  - 桁セルの記述子を既存のクラスタへ照合し、許容距離を超える場合は新しいクラスタとして登録する
  - 数字ラベルが未付与のクラスタを一覧できるようにし、後からラベルを与えられるようにする
  - 桁セルの並びを整数へ解決する。1 つでも未解決のクラスタを含む場合は「解決不能」を返し、推測で埋めない
  - クラスタの集合を不変な値として扱い、すべての操作が新しい集合を返すようにする
  - 完了状態: 同一の記述子が同じクラスタに、許容距離を超えて異なる記述子が別クラスタに割り当てられ、未解決を含む桁列が数値として解決されないことが単体テストで確認できる
  - _Requirements: 3.2, 3.3_
  - _Boundary: glyphBank_

- [x] 2.3 (P) ボタン表示からスロットの入力種別を推定する処理を作る
  - ボタン表示の 3 つの丸を横方向に等分割し、各位置の点灯有無を輝度で判定する
  - 点灯の組み合わせを入力種別へ対応付ける。対応関係は既存アーケードコントローラの同時押し合成規則（射撃のみ・射撃と格闘・射撃とジャンプ・格闘とジャンプ）と一致させる
  - 判定できない場合は推定結果を返さず、既定値で埋めない
  - 推定の確からしさを 0 から 1 の値として添える
  - 完了状態: 各点灯パターンに対応する入力種別が返り、どの丸も点灯していない場合に推定なしが返ることが単体テストで確認できる
  - _Requirements: 2.3_
  - _Boundary: slotClassifier_

- [x] 2.4 (P) CHARGE 表示の変化からチャージ入力を検出する処理を作る
  - 消灯から点灯への変化でチャージ開始、点灯から消灯への変化でチャージ終了のステップを記録する
  - スロットに設定されたチャージ種別（射撃系か格闘系か）に応じて、対応する入力種別を割り当てる
  - 一瞬のちらつきを拾わないよう、点灯の確定に連続フレーム数の下限を設ける
  - 輝度が閾値の近くにある変化は信頼度を下げ、確認を要する旨を添える
  - 走査の欠測区間をまたぐ変化はさらに信頼度を下げる
  - 完了状態: 合成した観測列に対して開始と終了が対で検出され、1 フレームだけのちらつきが検出されないことが単体テストで確認できる
  - _Requirements: 3.5, 3.6, 3.7_
  - _Boundary: chargeDetector_

- [x] 2.5 (P) ブーストゲージの急減からブースト候補を検出する処理を作る
  - 設定された時間窓の中で閾値を超える充填率の低下があった場合に、低下の開始時点でブーストダッシュのステップを記録する
  - 緩やかな連続消費では記録しない
  - ゲージの回復（増加）では記録しない
  - 閾値と時間窓を外から与えられるパラメータとして受け取り、既定値を持つ
  - 弾数由来のステップより必ず低い信頼度を割り当てる
  - 完了状態: 急減のみが検出され、緩やかな減少と回復が検出されず、信頼度が弾数由来より低いことが単体テストで確認できる
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 4.5_
  - _Boundary: boostDetector_

- [x] 2.6 弾数の推移から射撃系入力を検出する処理を作る
  - 連続するフレームの弾数を比較し、減少した場合にそのスロットの入力種別のステップを記録する
  - 増加（リロード）では記録しない
  - 連続して減少し続ける区間は、設定された間隔以内であれば減少の開始 1 点に畳む
  - 両フレームの弾数が数値として解決できない場合は、記述子の変化の有無だけを見て「方向不明」の低信頼ステップとし、確認を要する旨を添える
  - 走査の欠測区間をまたぐ変化はさらに信頼度を下げる
  - 完了状態: 合成した観測列に対して減少のみが記録され、増加が記録されず、連射区間が 1 件に畳まれ、未解決の桁を含む区間が方向不明として出ることが単体テストで確認できる
  - _Depends: 2.2_
  - _Requirements: 3.2, 3.3, 3.4, 3.5_

- [x] 2.7 検出器を統合して集計を返す処理を作る
  - 弾数・チャージ・ブーストの各検出結果をまとめ、時刻の昇順に整列する
  - 設計で定めた規則に従って信頼度を割り当て、すべてのステップが 0 から 1 の範囲の信頼度を持つようにする
  - 格闘入力を一切出力しない
  - 入力種別ごとの件数と総数を集計として返す
  - 同じ入力に対して常に同じ結果を返す純関数として保ち、画面描画の仕組みに依存させない
  - 完了状態: 3 種の検出結果が時刻順に統合され、格闘が含まれず、種別ごとの件数が正しく集計されることが単体テストで確認できる
  - _Depends: 2.4, 2.5, 2.6_
  - _Requirements: 3.5, 3.8, 5.3_

- [x] 3. 譜面の入出力

- [x] 3.1 (P) 譜面の直列化と読み込み検証を作る
  - 編集中のステップ列と出典情報から譜面を組み立てる。編集専用の内部情報（識別子・検出器の由来・確認理由）は出力に含めない
  - 出力は時刻の昇順に整列し、すべての入力種別が妥当であることを保証する
  - 読み込みでは未知の値をそのまま状態へ入れず、必ず検証を通す。不正な箇所は場所を示して列挙し、部分的な取り込みを行わない
  - 読み込んだ譜面を編集用のステップ列へ変換し、識別子を新規に採番する
  - 完了状態: 組み立て・直列化・読み込み・変換を往復させると識別子以外が一致し、不正な譜面が理由付きで拒否されることが単体テストで確認できる

  - _Requirements: 8.3, 8.6, 8.7_

  - 先頭に見出し行を 1 行持たせる
  - 完了状態: 生成された CSV の列構成が譜面のステップ項目と一致し、行数がステップ数と見出し 1 行の合計になることが単体テストで確認できる

- [x] 3.3 ファイルのダウンロードと読み込みの導線を作る

  - 時刻補正は出力時にのみ適用し、編集中の時刻には反映しない。編集用の全体オフセットと二重に適用されないようにする
  - JSON と CSV をそれぞれファイルとしてダウンロードできるようにする
  - ローカルの譜面ファイルを読み込み、検証結果をそのまま呼び出し側へ返す
  - 完了状態: 設定した出典と時刻補正が出力ファイルに反映され、読み込んだファイルの検証結果が成功・失敗の別とともに返ることを確認できる

  - _Requirements: 8.3, 8.4, 8.5, 8.6_

- [x] 4. 譜面編集の状態管理

- [x] 4.1 編集操作と逆操作を定義する
  - 現在位置へのステップ追加（由来は手動、信頼度は 1）、削除、コマ単位の時刻調整、入力種別の変更、全体オフセットの適用、検出結果の取り込み、全置換を扱えるようにする
  - 時刻調整と種別変更を自動検出のステップに適用した場合、そのステップの由来を手動へ、信頼度を 1 へ昇格させる
  - 入力種別の変更は既存の入力種別の値のみを受け付ける
  - 全体オフセットは全件へ同一値を加算して相対順序を保つ。時刻が負になる場合は適用自体を拒否し、切り詰めない
  - 検出結果の取り込みでは、方針が「自動検出のみ差し替え」のとき手動のステップを一切削除しない
  - すべての操作が、適用結果とそれを打ち消す操作の組を返すようにする
  - すべての操作の出口で時刻の昇順を保つ
  - 完了状態: 任意の操作列を適用してからすべて打ち消すと初期状態に戻ること、および手動ステップが差し替えで消えないことが単体テストで確認できる
  - _Requirements: 5.4, 7.1, 7.3, 7.4, 7.5, 7.6, 7.8_
  - _Boundary: chartReducer_

- [x] 4.2 編集フックに Undo・絞り込み・自動保存を持たせる
  - 直近 20 件の操作を打ち消せるようにし、上限を超えた分は古い方から捨てる
  - 入力種別・由来・最小信頼度による絞り込みを提供し、絞り込み後の一覧を返す
  - 再生位置に最も近いステップを求められるようにする
  - 編集内容を debounce してブラウザに保存し、保存失敗（容量超過）は編集を止めずに呼び出し側へ通知する
  - 完了状態: 21 回の操作後に最も古い操作が打ち消せなくなること、絞り込みが反映されること、編集後に保存内容が更新されることを確認できる
  - _Depends: 4.1_
  - _Requirements: 6.3, 6.5, 7.7, 8.8_

- [x] 5. フレーム供給層

- [x] 5.1 校正矩形ぶんの画素を取り出す処理を作る
  - 正規化座標の矩形を、フレームの実解像度に基づく画素座標へ変換する
  - 弾数領域はスロットに設定された桁数ぶんに等分割し、桁セルごとの画素として取り出す
  - CHARGE 領域・ボタン表示領域・ブーストゲージ領域をそれぞれ取り出す
  - 画面全体ではなく校正矩形の合計面積のみを扱い、取得した画素は呼び出しごとに独立したバッファとして返す
  - 完了状態: 与えた校正に対して桁数ぶんのセルと各領域が返り、返されたバッファが内部で再利用されていないことを確認できる
  - _Requirements: 2.2, 3.1_

- [x] 5.2 (P) 再生方式のフレーム供給を作る
  - 解析専用の非表示の動画要素を自ら持ち、閲覧用の要素とは共有しない
  - 再生倍率を上げて再生しながら、フレーム描画のたびにそのフレームのメディア時刻とともにフレームを供給する
  - 提示済みフレーム数の増分からフレームの取りこぼしを算出し、飛ばされた枚数を各フレームに添える
  - 中断の要求を受けたら速やかに供給を終える
  - 完了状態: 動画を 1 本流すとメディア時刻が単調非減少で供給され、中断要求で供給が止まり、閲覧用要素の再生位置が影響を受けないことを確認できる
  - _Requirements: 3.1, 5.5, 5.6_
  - _Boundary: playbackFrameSource_

- [x] 5.3 (P) シーク方式のフレーム供給を作る
  - 再生位置をコマ単位で進め、シーク完了を待ってからフレームを供給する
  - 再生方式と同一の供給契約に従い、呼び出し側から区別なく扱えるようにする
  - 中断の要求を受けたら速やかに供給を終える
  - 完了状態: 再生方式と同じ手順で消費でき、コマ単位の時刻でフレームが供給されることを確認できる
  - _Requirements: 3.1_
  - _Boundary: seekingFrameSource_

- [x] 5.4 供給方式を能力検出で選ぶファクトリを作る
  - フレーム描画の通知が使える環境では再生方式を、使えない環境ではシーク方式を選ぶ
  - 動画のメタデータ読み込みを待ち、デコード失敗と待機のタイムアウトを区別して返す
  - 選ばれた方式を呼び出し側が参照できるようにし、シーク方式では処理に時間がかかる旨を伝えられるようにする
  - 完了状態: 環境に応じて方式が切り替わり、読み込めない動画に対して理由付きの失敗が返ることを確認できる
  - _Depends: 5.2, 5.3_
  - _Requirements: 5.5_

- [x] 6. 動画プレイヤーと HUD 校正

- [x] 6.1 動画の読み込みと再生制御を作る
  - ローカルの動画ファイルを読み込み、尺と解像度を取得する。ファイルはブラウザ内に留め、どこへも送信しない
  - QuickTime 形式のファイルは、そのままでは主要ブラウザが再生を拒むため、内容を変えずに一般的な動画として扱い直してから読み込む
  - 読み込みに失敗した場合は、対象のファイル名と変換の案内を伴う失敗を返し、直前に読み込まれていた動画の状態を変更しない
  - ミリ秒単位の再生・一時停止・シークを提供する
  - コマ送りを 1/30 秒単位で前後に行い、移動先が動画の範囲を超えないようにする
  - 読み込んだ動画の参照を解放する手段を持たせ、読み込み失敗時にも確保した参照を破棄する
  - 完了状態: 動画を読み込むと尺と解像度が得られ、読み込めないファイルでは前の動画が保たれたままエラーが返ることを確認できる
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5_

- [x] 6.2 (P) 校正データの検証と永続化を作る
  - 武器スロットが 1 件以上あり、ブーストゲージの矩形が指定されていることを解析開始の条件として検証し、満たさない場合は不足している項目を列挙して返す
  - 桁数が不正なスロット、CHARGE 領域があるのに種別が未設定のスロットも不備として報告する
  - 校正をファイル名で引けるようブラウザに保存し、保存件数に上限を設けて古いものから捨てる
  - 同名ファイルの保存済み校正がある場合は再利用の候補として提示し、自動では適用しない。適用は動画の尺と解像度も含めた一致を確認したうえでユーザーが選ぶ
  - 完了状態: 必須領域が欠けた校正で不足項目が列挙され、保存した校正が同名ファイルの読み込み時に再利用候補として返ることを確認できる
  - _Requirements: 2.5, 2.6_
  - _Boundary: useCalibrationStore_

- [x] 6.3 (P) 動画プレイヤーの画面を作る
  - 閲覧用の動画表示と、再生・一時停止・シーク・コマ送りの操作列を配置する
