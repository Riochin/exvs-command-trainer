# 性能実測の記録（Task 10.6）

対象要件: 5.5（60 秒 1080p を 3 分以内）、5.6（走査中もページが応答する）、4.5（閾値変更の反映）

## 計測環境

| 項目 | 値 |
|------|-----|
| 機種 | Apple M4 / macOS 26.6.2 |
| ランタイム | Node.js v23.11.0 / Vitest 3.2.4（jsdom） |
| 計測日 | 2026-09-15 |
| 計測コード | `next/src/__tests__/performance/chartAuthorAnalysis.perf.test.ts` |

計測は本番と同じ関数（`reduceFrame` / `runDetectors`）をそのまま呼ぶ。写しは作らない。

## 計測できた項目

入力条件: 60 秒 / 30fps = 1,800 フレーム、武器スロット 5 件 × 2 桁、
桁セル 22×26px・CHARGE 64×20px・ブーストゲージ 420×14px（1080p HUD の想定寸法）。

| 項目 | 実測値 | 目標 | 判定 |
|------|--------|------|------|
| 観測（画素 → 観測値）1,800 フレーム合計 | **418 ms** | 走査全体 180,000 ms の一部 | 達成（走査持ち時間の 0.23%） |
| 同・1 フレームあたり | **0.232 ms** | 33.3 ms（30fps の 1 コマ） | 達成 |
| メインスレッドを手放すまでの最長区間（30 フレーム） | **8.5 ms** | 50 ms 未満 | 達成 |
| 検出の再実行（`runDetectors`、165 件検出） | **5.3 ms** | 500 ms 以内 | 達成 |
| 閾値変更後の再実行 | **2.8 ms** | 500 ms 以内 | 達成 |

`SCAN_YIELD_INTERVAL_FRAMES`（30）ごとの解放で 1 区間が 8.5ms に収まるため、
解析側が長タスク（50ms 超）を作ることはない。

## 計測できなかった項目と、その理由

テスト環境（jsdom）には動画のデコードも canvas も無いため、
以下は**実ブラウザでの計測が必要**であり、今回は未実測。

| 項目 | 状態 | 計測手順 |
|------|------|----------|
| 再生方式（`playbackFrameSource`）での通し時間 | 未実測 | 60 秒 1080p を読み込み、走査開始から完了までの経過時間（画面の「経過秒」表示）を記録する |
| シーク方式（`seekingFrameSource`）での通し時間 | 未実測 | rVFC を持たないブラウザ（または `supportsFrameCallback` を偽とした状態）で同じ計測を行う |
| 走査中のスクラブ | 構造的には担保 | 解析専用の `<video>` を別に持つため閲覧用の再生位置に干渉しない。`playbackFrameSource.test.ts` の「閲覧用要素の再生位置が影響を受けない」で検証済み |

### 既知の制約: シーク方式は目標未達の見込み

シーク方式は 1 フレームごとに `currentTime` の書き込みと `seeked` の待ち合わせを行う。
主要ブラウザのシーク往復は経験的に 30〜100ms 程度であり、1,800 フレームでは

- 30ms/フレーム → 約 54 秒（目標内）
- 50ms/フレーム → 約 90 秒（目標内）
- 100ms/フレーム → 約 180 秒（**目標の境界**）

となり、シークが遅い環境・コーデックでは 3 分の目標に届かない可能性が高い。
再生方式（rVFC + 再生倍率 4 倍）が使える環境では 60 秒のクリップを
15 秒程度で流し切れるため、この制約は rVFC 非対応環境に限られる。

**未解決の申し送り**: 選ばれた供給方式は `FrameSource.kind` で参照できるが、
現状その値は `useAnalysisRun` から UI へ公開されていない。シーク方式のときに
「時間がかかる」旨を画面へ出す導線は未実装。
